## Log

- **0.1** CI workflow (dashboard lint/tests/checks, agent on Python 3.11–3.13, shellcheck, Docker build). Fixed a shellcheck warning in `install.sh`. Agent suite verified locally on real Python 3.11.17 and 3.12.15.
- **0.2** `VERSION` file as the single version, `APP_VERSION` setting, version-sync test, `CHANGELOG.md`, tag-triggered release workflow (checksums, release notes, GHCR image).
- **1.1** `SystemState` model, watchdog thread pinging `WATCHDOG_URL`, downtime detection with a system notification to every channel + audit row, System page with relay/watchdog/backup/usage/version/config tiles.
- **1.2** Daily online snapshots with rotation (`BACKUP_DIR`, `BACKUP_KEEP`), `backup`/`restore` commands (restore refuses a running relay or corrupt file, keeps the replaced db), optional Litestream service. Fixed a YAML quoting issue in `docker-compose.yml`.
- **1.3** RFC 6238 TOTP on the standard library (`apps/users/totp.py`), `TOTPDevice` (encrypted secret, replay step) and hashed `RecoveryCode`s, second login step at `/login/verify/` (5-minute pending session, throttled), setup page with server-rendered QR (`segno`), Admin enforcement middleware, Admin reset on the user page, `manage.py reset_2fa`. Tests default enforcement off in `conftest.py` and test it explicitly.
- **1.4** Counting Redis client (`relay._CountingRedis`), agent-side estimate per received message, `RelayUsage` daily rows flushed every minute, month projection and cost on the System page. A misplaced `@cache` during the edit was caught by the tests.
- **1.5** Least-squares forecast over 7 days of hourly averages (`apps/alerts/forecast.py`), `Server.disk_full_at`, `DISK_FORECAST` alert (warning ≤ 7 d, critical ≤ 2 d, clears > 10 d), "fills in ~N days" on the dashboard and server page. Docs: configuration and deployment (backups, watchdog) updated; CHANGELOG updated.
- **2.0** Monitor `kind`/`target`/`options`/`secret_options`, `MonitorStatus.DEGRADED` ("Slow"), `MonitorCheck.degraded`, probe registry in `checker.py`, kind-aware form (fields shown per type with a little JS), list/detail show what's checked; uptime bars get a "slow" shade.
- **2.1** Heartbeat monitors fed by signed `ping` relay messages (`agent --job-ping`, `smctl ping`, `smctl run` which keeps the job's exit code); start→ok measures runtime; a missed deadline or reported failure is down at once; "Check now" never fakes a miss. Pings from legacy unsigned agents, forged pings and pings for another server's monitor are ignored.
- **2.2** TCP (optional TLS + certificate expiry), ping (system `ping`, loss → Slow), DNS (`dnspython`, expected answer, custom resolver), domain expiry (RDAP, warn < 30 d, critical < 7 d), HTTP POST/PUT, body, encrypted headers, keyword-absent, redirect control, slow threshold.
- **2.3** Channel registry (`apps/alerts/channels.py`) with structured `Message`s; 7 new kinds; secrets encrypted and never re-shown.
- **Security fix found on the way:** `netguard.create_connection` checked the peer only *after* connecting, so an Admin could tell open from closed internal ports by the error. It now resolves and refuses internal addresses before any connection and connects to the checked IP. Regression test added to `test_security.py`.
- **2.4** `apps/status`: pages, components with public names, incidents with updates; self-contained static HTML (no JS, dark mode, 90-day bars) + `status.json`; GitHub contents-API publisher (no empty commits, CNAME for custom domains, 30-min backoff on failure) run by the relay every 2 min or at once after an incident; preview, ZIP download. Sidebar: Infrastructure → Status pages.
- **Visual check** of System, 2FA setup, monitor list/form, channel picker, status page (dashboard + public, light/dark/mobile) on the demo database. Fixed: field order (Type first), list copy, short type tags, 2FA back arrow, webhook label.
- **3.1** Agent collects top processes (CPU and memory), temperatures (psutil sensors), NVIDIA GPUs (`nvidia-smi`) and containers from cgroup v2 files (CPU % from usage deltas, memory) without the docker group; `docker ps` adds names and stopped containers when enabled. Heartbeats advertise `capabilities.features`. Dashboard stores `Server.inventory`, alerts on a running container that stops and on sensors at their high/critical marks, and shows Top processes / Containers / Hardware cards on the server page.
- **3.2** Stdlib 5-field cron (`apps/operations/cron.py`, DST-safe). `Schedule` model (servers + groups + environments resolved at run time, rollout options) run by the relay, claim-then-run so a slot runs once, missed slots run once. Rolling jobs: `Command.batch` + `WAITING` status, `Job` rollout state machine (pause, stop on failure, health gates needing a fresh check, gate timeout), Resume/Abort (audited), batch timeline on the job page.

- **Docs for 3.1/3.2**: agent.md (What the agent reports, Scheduled and rolling jobs), architecture.md (rolling jobs, schedules), configuration.md (`[agent] inventory`, `[docker] names`), `agent.example.toml`.
- **3.3** Agent `_upgrade` built-in behind `[agent] remote_upgrade` (validates `vX.Y.Z` ref, 6 SHA-256 sums, command id; writes `upgrade-request.json` atomically, reports "running"), `--command-result` for root to report back, `server-monitor-upgrade.path/.service` (installed by `install.sh`, path unit enabled only when opted in). `smctl remote-upgrade on|off`, `smctl upgrade --from-request` (O_NOFOLLOW, regular single-link file ≤ 4 KB, deleted on read, content never echoed, config re-checked, recorded repo only, installer output returned with colours stripped). Dashboard: `agentdist.upgrade_args()` (tag + all 6 checksums), `_upgrade` Admin-only with skip reasons, `upgrade_agents` rolling job, Upgrade agent now / Upgrade all outdated, "update available" on the server page. Docs: agent.md (threat note), security.md, CHANGELOG. The root handler was first blocked by Claude Code's safety classifier; written after the owner asked to complete all tasks.
- **3.4** `Monitor.check_from_dashboard/probe_servers/quorum/location_states`, `MonitorCheck.location`; quorum in `checker.record` (per-location row + outcome row), `reevaluate` for agent-only monitors; assignments in `cfg` re-sent only when the agent's echoed `probes_rev` differs; agent `Prober` thread with its own address guard and IP pinning; stats read outcome rows only; monitor form *Where from* (agents-only allows internal URLs; secret headers refused); Locations card on the monitor page.
- **4.1** `apps/api`: `ApiToken` (SHA-256, prefix, scope, expiry, last used), bearer auth decorator (CSRF-exempt, session ignored, per-token rate limit, bad-token throttle per IP), endpoints for servers/monitors/alerts/jobs/commands, `POST /api/v1/jobs/` through `create_job` (no shell or `_` actions), `/metrics` Prometheus text; audit rows record `via: API token`; token page under My account.
- **4.2** `MetricRollup` + `MonitorDaily`, `apps/fleet/rollups.py` (idempotent, catch-up, prune) run hourly before the forecast; charts 7d+ read rollups (+30d/90d ranges); `daily_uptime` merges rollups and raw checks; per-mount forecast (`forecast.soonest`).
- **4.3** Agent `tail_follow` (file follow with rotation/truncation, journalctl `--unit` for declared systemd services, filter, 10 min cap, flood-bounded) advertised as `log_follow`; dashboard args/validation, `journal:` picker entries, Follow/Stop on the server page, `stop_follow` (audited `command.stop`).
- **4.4** `manifest.webmanifest`, `/sw.js` (offline page, static cache, push + notification click limited to this origin), `/offline/`, icons (SVG + PNGs rasterised in pure Python), Install app button; `apps/alerts/webpush.py` (RFC 8291 + VAPID, key encrypted in `SystemState`), Browser push channel kind with in-page subscribe.
- **4.5** `apps/users/sso.py` (`SSOBackend` on mozilla-django-oidc, PKCE), `SSOIdentity`, group → role mapping each sign-in, local password refused for linked accounts, 2FA middleware skips SSO sessions, "Sign in with …" on the login page, `/oidc/` mounted only when configured.
